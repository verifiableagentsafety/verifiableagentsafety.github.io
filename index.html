Description

What can we prove about an AI agent before it acts, while it runs, and after it changes?

AI agents turn model outputs into tool calls, persistent state changes, and interactions with other agents. A plausible plan can still exceed a user's authority, reveal protected information, or repeat an external action after a retry. These failures require reasoning about the interaction between a learned policy, its execution environment, and the mechanism that enforces the user's constraints.

The Verifiable Agent Safety workshop brings together machine learning, formal methods, programming languages, security, and AI safety researchers. Our focus is verifying the agent system itself: its permitted effects, workflow, state transitions, communication, and oversight mechanisms. We ask which properties can be specified precisely, checked independently, and preserved throughout execution.

We will study how learning can make these guarantees practical through specification synthesis, proof generation, verification feedback, and adaptation that preserves established invariants. Lean-based mechanization provides a concrete starting point; contributions using other proof assistants, verified monitors, model checking, or sound decision procedures are welcome when they address a clearly stated agent-safety property.

Call for Paper Topics

Topics include, but are not limited to:

  1. Specifications that capture user intent: Permission, information-flow, resource, and task-completion contracts; autoformalization, ambiguity and vacuity detection, and human correction.
  2. Safe actions and runtime enforcement: Proof-carrying actions, verified tool interfaces, complete mediation, fail-closed execution, and connections between abstract guarantees and their implementation.
  3. Long-horizon composition and adaptation: Preserving invariants and obligations across memory, delegation, workflow revision, retries, checkpointing, restoration, forking, and merging.
  4. Communication, evidence, and oversight: Verifiable multi-agent protocols, provenance, adversarial debate, and the assumptions placed on observations, semantic interpretations, and judgments.
  5. Learning and evaluation with guarantees: Verification feedback for training and inference; specification gaming, guarantee coverage, attacks, task success, verification costs, and unnecessary refusals.

Call for Papers

We invite formal results, verified monitors, empirical studies, replications, and carefully analyzed counterexamples. Complete system verification is not required. Papers describing demonstrations may include a video and artifact link.

One paper track: 4–9 pages, excluding references and optional appendices. Submissions will undergo double-blind review on OpenReview. The workshop is non-archival.
